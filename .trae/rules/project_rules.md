# 项目规则（Trae 每次会话自动注入）

## 启动指令（最高优先级）

每次会话开始，无论任务大小，必须按 [AGENT.md](../../AGENT.md) §1 顺序完成启动检查：README.md → docs/ → AGENT.md → 代码结构 → `git status` → 进度与最近提交 → 判断任务类型；然后先向用户汇报**当前项目状态、任务目标、已知约束、尚未确定的决策**。未经用户允许，不得进入下一阶段。

## 核心规则速览

> 本速览仅为防遗漏摘要；**一切以 AGENT.md 最新内容为准**，冲突时以 AGENT.md 为准。

1. **协作模式（AGENT.md §0）**：人负责决策（业务规则、功能范围、数据结构、API 契约、架构方案、阶段推进、Git 提交），Agent 负责执行（分析、方案、编码、测试、文档、汇报）。Agent 不得因"看起来合理"自行确定尚未明确的业务规则。
2. **阶段门禁（AGENT.md §3~§6、§15）**：新业务模块禁止直接编码。先需求分析（区分「原始需求 / 推导 / Agent 建议」，多方案列选项交用户决定，推荐 ≠ 最终）→ 业务设计（流程/实体/数据关系/API/状态/异常/权限）→ 技术方案 → 用户确认后才编码。
3. **编码原则（AGENT.md §6、§13）**：严格按已确认方案实现；发现原方案问题立即停止，按「原方案/问题/影响/建议」格式报告，等待用户决定；最小修改，发现可优化处只记录报告，不擅自扩大修改范围。
4. **模块汇报（AGENT.md §7）**：模块完成后按「功能 / 文件 / 业务 / 技术 / 测试 / 风险 / 文档」七项汇报，等待用户模块级审核。
5. **测试覆盖（AGENT.md §9）**：至少覆盖正常流程、参数异常、边界、权限异常、重复操作、数据不存在、数据冲突、未登录；测试失败先分析定位再修复重测。
6. **Git（AGENT.md §10）**：Agent 仅可执行 status/diff/log；`commit` / `push` 必须用户明确要求；每模块完成后可建议提交并等待用户决定。
7. **交互留痕**：与用户交互的重要内容（方案、批改意见、关键决策、验证结论、提交记录）须同步写入 README.md「8. AI 辅助开发记录」章节，保持需求 ↔ 设计 ↔ AI 交互 ↔ 代码 ↔ Git 可追踪。
8. **严禁行为（AGENT.md §12）**：未经用户确认，不得擅自加需求、改业务规则、改数据库核心结构、改 API 契约、加角色、加复杂中间件、引入大型依赖、重构无关代码、提交/推送 Git、删除或覆盖用户已有代码、把 Agent 推测说成原始需求。
9. **输出语言（AGENT.md §14）**：默认中文（方案、汇报、注释、测试报告、提交建议、文档说明）。
