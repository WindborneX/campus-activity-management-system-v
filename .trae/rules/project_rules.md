# 项目规则（Trae 每次会话自动注入）

## 启动指令（最高优先级）

每次会话开始，无论任务大小，必须先完整读取项目根目录的 [AGENT.md](../../AGENT.md) 与 [README.md](../../README.md)。新模块未经人审批前，禁止修改核心代码。

## 核心规则速览（以 AGENT.md 最新内容为准）

1. **协作模式**：人负责业务决策与审批，Agent 负责分析、实现、验证；不得自行确定业务规则、扩大范围或引入未批准技术；V1.0 仅 STUDENT/TEACHER，范围仅 F1~F9 / R1~R7；默认中文、最小修改、禁止提交敏感信息。
2. **模块标准流程**：提出模块 → Agent 分析现有代码 → 给出「①核心业务流程 ②关键业务规则 ③实现方案（改哪些文件/为什么） ④需注意的问题（**最多 3 个**）」→ 人审批 → 实现。一次给全，不挤牙膏。
3. **审批机制**：按「【等待审批】模块名（F/R 编号）+ ①②③④ + 需要人工确认」格式输出；审批通过前不写代码；实现中发现需扩大修改范围 → 暂停并说明，不静默扩大。
4. **实现与验证**：严格按批准方案实现、复用现有代码；测试覆盖正常/边界（重复、不存在、已满、非法参数）/权限（未登录、角色越权、跨用户数据）；完成后简短汇报：做了什么 → 测试结果 → 剩余风险。
5. **Git**：一个业务闭环一个提交；commit/push 由用户明确决定，Agent 只能建议；禁止改历史、强推、大杂烩、提交敏感信息。
6. **AI 使用记录（AGENT.md §5）**：关键步骤（方案、批改意见、决策、验证结论、提交）经用户确认后**必须立即写入 README「8. AI 辅助开发记录」；未写入前该确认不算完成**；重点记录「Agent 提出了什么，人为什么接受、修改或拒绝」。
7. **完成标准（AGENT.md §6）**：方案经审批、实现编译通过、正常/边界/权限测试通过、风险已说明、README §8 已留痕、Git 提交经用户同意、人能解释业务逻辑——缺一不可。
