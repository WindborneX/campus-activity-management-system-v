## 启动指令（最高优先级）

每次会话开始，无论任务大小，必须先完整读取项目根目录的 [AGENT.md](../../AGENT.md) 与 [README.md](../../README.md)，并按 AGENT.md §0「启动检查」执行。未完成启动检查前，不得修改代码。

## 核心规则速览

> 本速览仅为防遗漏摘要；**一切以 AGENT.md 最新内容为准**，冲突时以 AGENT.md 为准。

1. **开发前（AGENT.md §1.1）**：新模块开发前必须先向用户提交实现方案（文件清单、接口/页面设计、关键要点、验证方式），经批改确认后才编码。
   - 必须等待用户确认：新模块、架构调整、数据库结构调整、新增依赖、修改既有业务规则、超出 README 范围的功能；
   - 可直接处理、事后报告：简单 bug 修复、格式调整、明显错误修复。
2. **开发前检查（AGENT.md §1.2）**：`git status`、当前分支、最近提交、README §6 状态、未提交修改；**不得覆盖用户已有的未提交修改**。
3. **开发后（AGENT.md §1.3）**：总结完成业务（功能点 F 编号、业务规则 R 编号、验证情况）；是否 commit / push 由用户决定，未经同意不得提交。
4. **最小修改原则（AGENT.md §2）**：改现有优先于新建、复用优先于重写、局部修改优先于重构、不提前设计、不增加复杂架构。
5. **范围红线（AGENT.md §3）**：只实现 README 定义的 F1~F9 / R1~R7，禁止擅自扩大功能；密码、Token、密钥等敏感信息不进代码和 Git。
6. **交互留痕（AGENT.md §1.3）**：与用户交互的重要内容（方案、批改意见、关键决策、验证结论、提交记录）必须在完成后同步写入 README.md「8. AI 辅助开发记录」章节，保持需求 ↔ 设计 ↔ AI 交互 ↔ 代码 ↔ Git 可追踪。
